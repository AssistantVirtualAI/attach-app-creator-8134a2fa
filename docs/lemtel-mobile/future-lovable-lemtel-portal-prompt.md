# Prompt unique pour un futur projet Lovable Lemtel séparé

> Crée un **nouveau projet Lovable distinct nommé “Lemtel Portal”**. Ne modifie, ne lis, ne migre, ne synchronise et ne déploie jamais le projet Lovable existant ni la branche `Planipret`. Ne connecte pas GitHub automatiquement dans cette étape.
>
> Construis un portail d’administration de staging Lemtel, moderne, accessible et bilingue français/anglais, destiné à des administrateurs internes. L’interface doit contenir : une page de connexion, un tableau de bord d’état, une liste d’utilisateurs/organisations, une page d’annuaire privé de contacts, une page de diagnostics WSS, une page de configuration mobile et une page “Préparation de recette”. Utilise des données de démonstration locales clairement étiquetées “DÉMO — aucune donnée réelle”, sans appeler une base de données, Supabase, FusionPBX ou un service externe.
>
> Applique ces contraintes : aucun secret, URL privée, clé Supabase, identifiant SIP, donnée Planiprêt, donnée de production ou adresse IP ne doit apparaître dans le code, les textes ou l’interface. Ne crée aucune migration SQL, fonction serveur, intégration PBX, automatisation, DNS, workflow de déploiement ou synchronisation GitHub. Ne prétends pas que les appels ou notifications fonctionnent.
>
> Pour la page “Préparation de recette”, affiche explicitement les prérequis encore requis : extension de test, SIP/WSS/TURN de recette, iPhone avec signature/provisionnement/TestFlight, Android de test, paquet Desktop de test, PushKit/CallKit, FCM, tests Wi‑Fi/LTE/5G/Bluetooth/téléphone verrouillé, et approbation avant cutover. Ajoute des états visuels “Prêt”, “À confirmer” et “Bloqué” avec des données de démonstration.
>
> Fournis d’abord une interface fonctionnelle en preview Lovable. À la fin, résume les écrans construits et demande une approbation explicite avant toute connexion GitHub ou backend.
